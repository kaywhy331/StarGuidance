# Known gaps and production gates

This branch is a safe-beta candidate, not a public-production approval. The implemented security boundaries are useful now: conventional email/password Auth, versioned consent receipts, encrypted profile/question storage, forced-RLS user isolation, database-enforced snapshot immutability (guard trigger plus narrowed grants, migration 0009) with application-enforced draw lineage, deterministic AI fallback, output safety validation, scoped export/deletion, security headers, and fail-closed runtime selection. The gates below are deliberately explicit so a green build cannot be mistaken for business, legal, operational, or provider approval.

## Exact-commit release evidence

- Migrations `0005_bumpy_moon_knight` through `0013_checkout_report_source` must be applied to the non-production Supabase staging project. `0005` scrubs legacy plaintext birth metadata and adds profile-root, initial follow-up, and reading-idempotency constraints; `0006`–`0010` add distributed rate limiting, durable interpretation jobs, subject-bound job policy, snapshot immutability, and deletion receipts; `0011` adds deck/spread kill switches and configurable follow-ups; `0012` adds the forced-RLS report queue and profile-independent commerce retention; `0013` stages the encrypted derived report source before Checkout. The protected workflow must then prove schema readiness, two-user isolation, both queues, locked-draw recovery, export, deletion/payment separation, key rotation/rollback, synthetic cleanup, and the deployed commit.
- Public `/api/health` proves only liveness. The protected HMAC-authorized readiness probe must pass for the exact deploy being promoted; an earlier green run does not transfer to a later commit.
- Full Node 24 CI, browser E2E, Python 3.12 checks, hashed lock installs, production dependency audit, migration rehearsal, secret scan, and Netlify deployment must all be green at the same head.
- `main` now enforces required status checks (`web`, `profile-engine`, `e2e`, `secret-scan`, `migration`, `guard`, `verify`), PR-only merges, required conversation resolution, and blocked force-push/deletion, including for administrators (applied and verified via the GitHub API 2026-08-06). Required approving reviews remain set to zero: GitHub never counts a PR author's own approval toward that count, and no second reviewer is configured yet. The draft PR must not be merged by this implementation lane until an independent reviewer is assigned.

## Product-flow gaps

- Live interpretation now runs through a durable, idempotent job (migration `0007`, `packages/database/src/interpretation-jobs.ts`): the draw-creation request enqueues the job in the same transaction as the reading and draw, then makes one best-effort inline attempt to keep today's near-synchronous latency in the common case. The provider adapter intentionally makes one bounded request per claimed attempt; it does not retry inside an HTTP request. Transient timeout/provider retry belongs to the durable job layer, which applies capped backoff while preserving the locked draw and prevents stacked in-request latency or duplicate untracked calls. If the inline attempt is interrupted or fails transiently, the job stays durably claimable — a Netlify-scheduled function (`netlify/functions/process-interpretation-jobs.mts`, every minute) calls the bearer-secret-protected `POST /api/internal/interpretation-jobs`, which drains a batch. Worst-case recovery latency for that backstop path is therefore about a minute, during which the client (`apps/web/src/app/session/[id]/reading-scene.tsx`) polls rather than assuming the one-time fetch on mount is still current. Requires `INTERPRETATION_WORKER_SECRET` configured wherever the "supabase" runtime adapter runs, and `NEXT_PUBLIC_APP_URL` resolvable from the Netlify Functions runtime (not just the browser) so the scheduled function knows where to call back. Standalone Netlify Functions cannot import `postgres`/`drizzle-orm` at all — Netlify's zip-it-and-ship-it bundler fails to resolve them at runtime (`netlify/zip-it-and-ship-it#869`, confirmed here across three bundler configurations) — which is why the actual claim/AI-call/write work runs behind the Next.js/`@netlify/plugin-nextjs` path instead of in the scheduled function itself.
- The sanctuary now offers an explicit deck-cut choice (Cut / Skip cut), intentional per-card click/tap/keyboard reveal with a Reveal-all convenience control, an early Finish-shuffling control, and persistent in-app motion/sound controls seeded from the OS preference (PRD UX-002/UX-004/UX-006/UX-009). Cut choice and revealed indexes recover after interruption, and completed history entries open a direct pre-revealed result route. Automated coverage does not replace the manual keyboard/screen-reader/real-device review below.
- Follow-up count and normalized same-question cooldown are server-configurable (`READING_FOLLOW_UP_LIMIT=1`, `READING_REREAD_COOLDOWN_MINUTES=30` by default), and the repeat check reads durable user history so it holds across instances. There is still no paid/free entitlement tier, long-horizon reading allowance, or cross-account abuse signal; define those policies before wider access.
- Private resonance/helpfulness/comment feedback is implemented, encrypted, and included in export. Scheduled outcome reminders and the separate occurred/partial/did-not-occur/unclear research schema are intentionally not represented by this MVP feedback: RES-008 is deferred pending reminder consent, retention, notification, and research-governance decisions; RES-009 becomes applicable when that outcome surface is activated.
- Reading history now shows spread display names plus follow-up, feedback, and profile-report state. Reports expose their own pending/ready/failed pages and an authenticated same-purchase retry, but a standalone purchased-report history, support/admin views, non-sensitive trace lookup, model kill switch, and operator queue console are still absent; deck and spread kill switches are present in migration `0011`.

## Reports and commerce

- New reports are hidden and checkout/webhooks fail closed unless `ENABLE_PROFILE_REPORTS=true`; button visibility separately requires `NEXT_PUBLIC_ENABLE_PROFILE_REPORTS=true`. Both default false and should remain false in the safe beta.
- Stripe signature, reconciliation, replay, refund, dispute, entitlement, and revocation behavior has automated coverage, but credentialed test Checkout/webhook/refund UAT is still required in an isolated commerce deployment.
- Stripe fulfillment now atomically grants one entitlement, creates one pending report, and enqueues one durable report job before acknowledging the verified event. The scheduled drain retries with capped backoff; the UI polls explicit pending/ready/failed states and can re-enqueue the same retained source without another charge. The credential-free local adapter remains intentionally synchronous. Public launch still requires credentialed Stripe lifecycle UAT, standalone purchased-report history/support recovery, optional notification policy, and finance approval.
- The web report is browser-printable but there is no accessible PDF artifact or web/PDF content-parity test. Pricing, taxes, receipts, refunds/chargebacks, finance retention, support ownership, and launch-region policy remain owner decisions.
- Supabase Storage is not used. If report/PDF artifacts are later stored there, private buckets and object-level RLS need their own reviewed migration and isolation tests.

## Authentication, privacy, and operations

- Routine login uses email and password and sends no email. The owner must choose whether signup confirmation is required; if it is disabled, addresses are not verified. If enabled, delivered confirmation and recovery links need an owner-inbox, cross-browser smoke test using the reviewed token-hash templates.
- Request limits are bounded and ignore spoofable `x-forwarded-for`. On the `supabase` runtime adapter they are now enforced by an atomic Postgres function (migration `0006_rate_limit_buckets`, one round trip, `starguidance_app`-only, forced RLS) instead of an in-process map, so limits hold across multiple serverless instances; a failed check fails closed. The `local` adapter (dev/test) keeps the original in-process limiter. Covered by `packages/database/src/rate-limits.integration.test.ts` including a concurrency test, plus `apps/web/src/lib/request-security.test.ts` for the local path.
- Provider dashboard review remains outstanding for Netlify, Supabase, Render, the AI provider, Stripe, and any telemetry vendor: retention, region, training use, subprocessors, role access, deletion/export, logs, backups/PITR, and incident auditability.
- Production still needs managed key generation/escrow and cutover, provider-hosted restore rehearsal with approved RPO/RTO, approved retention schedules, named responders, customer-support procedures, privacy-safe traces/metrics/alerts, and regional crisis resources.
- The versioned beta Terms, Privacy Notice, 18+ policy, profile-personalization disclosure, deletion behavior, and consent language are engineering controls and draft copy—not legal advice or counsel approval. A responsible legal/privacy owner must approve them for selected launch regions.

## AI, calculations, and content

- Deterministic interpretation is the safe default. Live Groq remains disabled unless `AI_SAFETY_EVALUATION_APPROVED=true`; production also needs a signed model-specific safety/grounding evaluation, restricted-profile-leakage tests, no-retention contract/configuration, redaction verification, and cost/latency budgets.
- Western astrology, BaZi, and planetary angularity correctly return unavailable. Their licensing, conventions, geocoder/historical-timezone handling, reference suites, and named expert review remain activation gates.
- Pythagorean v3, Dreamspell v2, and Nine Star Ki now have digest-pinned 60/60/100-case internal regression matrices, including component-wise master numbers, Latin-Extended names, leap dates, non-leap centuries, and every fixed monthly Nine Star Ki boundary. These internal worksheets are not approved independent sources: Dreamspell remains `implemented_pending_approved_reference_dataset`, Nine Star Ki remains convention-bound pending independent reference review, and numerology still needs domain-owner certification. All spiritual-system copy and artwork need a final commercial rights/attribution register and domain-owner approval.
- Automated accessibility tests do not replace manual keyboard/screen-reader/text-zoom review, accessible PDF review, or real-device animation/performance testing. Deploy-preview toolbar frames are excluded only because they are host-injected; the suite separately asserts that the application embeds no frames.

No production payment, live AI, public launch, or calculation feature should be described as verified until its exact evidence and accountable approval are recorded.
