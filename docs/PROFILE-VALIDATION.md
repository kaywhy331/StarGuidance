Numerology letter mapping cycles A–I = 1–9, J–R = 1–9, S–Z = 1–8. Only A/E/I/O/U are vowels in this version. Middle names and entered suffixes participate; punctuation is ignored; NFKD and the documented Latin-Extended allowlist produce a separate derived rendering. Unsupported non-Latin names are not transliterated. These rules, including Y and suffix handling, need reviewer acceptance, not silent changes under v3.

The no-leap ordinal deducts all Gregorian February 29 dates on or before a date. The fixtures cover 1600/2000/2400 leap centuries and 1700/1800/1900/2100 non-leap centuries. Nine Star Ki uses fixed civil boundaries (Jan 5, Feb 4, Mar/Apr/May 5, Jun 6, Jul/Aug 7, Sep/Oct 8, Nov/Dec 7), not astronomical instants; K001–K024 bracket every boundary. The 100-row set also covers all 81 Principal/Character pairs. Energy wraps Principal − Character + 5 into 1…9; this is the selected Lo Shu convention, not a universal third-star rule.

## Snapshot and missing-context checks

`tests/test_profile_reference_trace.py` adds four worked numerology cases and four API capability cases. Date-only, location-only, time-only and time-with-place inputs retain identical date-based calculations and traits for the same name/date. They return Core, Location enhanced, Core and Complete respectively; Western astrology and BaZi remain unavailable throughout. Dreamspell/Nine Star Ki traits remain uncertain. These are capability states, not independent proof that the personality descriptions are valid.

`apps/web/src/lib/repositories/profile-versioning.test.ts` saves a synthetic historical v2 snapshot, locks a real configured spread and deterministic output against it, then saves a v3 snapshot with optional time/place. It asserts increasing snapshot versions, a shared profile root, distinct snapshot IDs, new active selection, unchanged old encrypted calculations, unchanged reading/output, historical snapshot lookup and cross-user refusal. The historical encrypted Life Path 4 is a supplied fixture: the test does not execute a retired v2 engine. The test uses the local repository and application encryption; it is not hosted PostgreSQL/RLS verification or proof of concurrent-write behavior. Existing database migration tests check snapshot immutability DDL separately.

Future calculation, dataset or convention changes require a new version, approved dataset identity/digest, and new snapshots. Keep old rows, locked draws and outputs addressable. The current web boundary pins engine versions through `CALCULATION_SYSTEM_VERSIONS`; mismatches must fail the contract rather than silently adopting new calculations.
